# Iteration 02 dashboard verification

The dashboard reads the original Iteration 01 snapshot contract. It validates run identity, provenance, row reconciliation, join cardinality, analytics keys and counts, quality scenario identity, and replay measurements. It reads Parquet lazily when a recording is selected. No Spark code, data cache, snapshot content, or existing regression test was rewritten.

## Commands

From the VitalFlow directory, with its existing Python 3.12.14 virtual environment:

```sh
.venv/bin/python -m pip install -e '.[dashboard,dev]'
.venv/bin/python -m pip check
.venv/bin/python -m streamlit run dashboard/app.py --server.headless true --server.port 8512
.venv/bin/python -m pytest -q --junitxml=outputs/dashboard-qa/pytest.xml
.venv/bin/ruff check .
.venv/bin/ruff format --check .
```

The project keeps PySpark 4.2.1 and the existing Java 25.0.4.1. The dashboard extra uses Streamlit 1.51.0, Plotly 6.4.0, pandas 2.3.3, and PyArrow 21.0.0. The first three were already pinned in Iteration 01; PyArrow is now a direct dependency because the Explorer reads Parquet without Spark. Installing the dashboard extra resolved the transitive `packaging` dependency from 26.3 to 25.0 to satisfy Streamlit 1.51.0's `packaging<26,>=20` constraint. `pip check` passed.

The optional browser script is separate from app dependencies. On a machine with Chrome and Node.js:

```sh
qa_tools=$(mktemp -d /tmp/vitalflow-browser.XXXXXX)
npm install --prefix "$qa_tools" playwright --no-audit --no-fund
NODE_PATH="$qa_tools/node_modules" node scripts/dashboard_browser_qa.cjs
```

Keep the dashboard running on port 8512, or set `VITALFLOW_QA_URL` to its local URL. `VITALFLOW_QA_CHANNEL` can override the installed Chrome channel. The script uses the real 53-recording evidence, blocks external HTTP and WebSocket destinations, checks layout overflow and interaction state, and writes PNGs under `outputs/dashboard-qa/screenshots/`.

## Evidence freshness and limits

- The cache key includes the project root, mode, and relative file names, inode, size and nanosecond modification time for required artifacts. Parquet uses a second key that includes its parts and the selected recording. A new snapshot is picked up on the next full interaction or browser refresh; a playback in progress stays on its loaded evidence until the next full interaction. Reads reject changes detected mid-load.
- The Overview can still render when Parquet is missing. The Explorer explains how to regenerate the selected run; it never substitutes another run. `VITALFLOW_PROJECT_ROOT` optionally points the app at another compatible checkout for testing or a portable evidence copy.
- Recorded arrival intervals drive playback. It is an animation of the archived experiment, not a new processing run. The first batch has no measured interval; the per-batch throughput is rows divided by measured Spark ingest/processing time.
- Source missingness comes from blank and NaN counts. Overview completeness uses retained rows × four channels. The original audit records the count and recording ID for invalid times; it does not embed the rejected raw row. Keep raw Fix files out of the demo.
- The dashboard is read-only and local. The evidence download offers the existing files; no report publication, final video, or PDF was performed.
